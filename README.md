# PStock

PStock is a full-stack stock price prediction platform that uses a trained AI/ML model to predict future stock prices. The application provides a Django REST Framework backend, a React.js frontend, PostgreSQL for persistent data storage, and JWT-based authentication.

> **Disclaimer:** PStock is a software project for stock-price prediction and educational/research purposes. Predictions generated by the application should not be considered financial advice.

## Features

* User registration and login
* JWT-based authentication
* Role-based permissions
* RESTful API built with Django REST Framework
* AI/ML-powered stock price prediction
* Trained Keras/TensorFlow prediction model
* Stock market data retrieval using `yfinance`
* File uploads
* PostgreSQL database
* Django Admin panel
* Interactive API documentation with Swagger and ReDoc
* Redis support for caching/background communication
* Dockerized backend and frontend
* Nginx reverse proxy/static-file serving
* Automated testing with pytest
* CORS support for frontend/backend communication

## Architecture

PStock is organized as a separate frontend/backend application:

```text
                         ┌────────────────────┐
                         │      React.js       │
                         │      Frontend       │
                         └─────────┬──────────┘
                                   │ HTTP/REST
                                   ▼
                         ┌────────────────────┐
                         │       Nginx        │
                         │ Reverse Proxy      │
                         └─────────┬──────────┘
                                   │
                                   ▼
                         ┌────────────────────┐
                         │ Django REST API    │
                         │      Backend       │
                         └──────┬─────┬───────┘
                                │     │
                    ┌───────────┘     └────────────┐
                    ▼                              ▼
             ┌─────────────┐                ┌─────────────┐
             │ PostgreSQL  │                │    Redis    │
             │  Database   │                │ Cache/Async │
             └─────────────┘                └─────────────┘
                               
                         ┌────────────────────┐
                         │  Trained Keras     │
                         │  Prediction Model  │
                         └────────────────────┘
```

### Prediction Flow

1. The user authenticates with the application.
2. The frontend sends a request to the Django REST API.
3. The backend retrieves the required stock-market data.
4. Data is prepared and transformed for the trained ML model.
5. The Keras/TensorFlow model generates the prediction.
6. The backend returns the prediction through the REST API.
7. The React frontend displays the prediction to the user.

## Environment Configuration

Create the environment file from the provided example:

```bash
cd backend
cp .env.example .env
```

The environment file should contain values similar to:

```env
SECRET_KEY=change-me
DEBUG=True

POSTGRES_USER=mlpostgres
POSTGRES_PASSWORD=mlpassword
POSTGRES_DB=mldb
POSTGRES_APP=mlpostgresql
POSTGRES_PORT=5433
```

### Production Security

Do **not** use the example `SECRET_KEY` or development credentials in production.

For production deployments:

* Generate a strong, unique Django `SECRET_KEY`.
* Set `DEBUG=False`.
* Use strong PostgreSQL credentials.
* Store secrets outside source control.
* Configure `ALLOWED_HOSTS`.
* Configure HTTPS.
* Restrict database access.
* Review CORS settings.
* Use secure JWT configuration.
* Avoid committing `.env` files to Git.

## Installation

### 1. Clone the Repository

```bash
git clone <repository-url>
cd pstock
```

### 2. Configure the Backend

```bash
cd backend
cp .env.example .env
```

Update `.env` with the appropriate database and application configuration.

### 3. Build the Backend

```bash
docker compose build
```

### 4. Start the Backend Services

```bash
docker compose up -d
```

The backend Compose stack includes:

* Django backend
* PostgreSQL 14
* Redis
* Nginx

### 5. Run Database Migrations

Run Django migrations inside the backend container:

```bash
docker exec -it backend bash
python manage.py migrate
exit
```

Alternatively:

```bash
docker exec -it backend python manage.py migrate
```

### 6. Create a Django Superuser

To access the Django Admin panel:

```bash
docker exec -it backend python manage.py createsuperuser
```

Follow the prompts to create the administrator account.

### 7. Backend Development Server

If the Docker image/container is configured to expose Django's development server, the API can be accessed at:

```text
http://localhost:8000/
```

For development, the server can also be started manually inside the container:

```bash
docker exec -it backend python manage.py runserver 0.0.0.0:8000
```

> For production, use the project's Gunicorn/Daphne configuration rather than Django's `runserver`.

## Docker Services

### Backend Compose

The backend stack contains four services.

| Service        | Image / Build    | Purpose                            | Port   |
| -------------- | ---------------- | ---------------------------------- | ------ |
| `mlpostgresql` | PostgreSQL 14    | Application database               | `5433` |
| `backend`      | Local Dockerfile | Django REST API                    | `8000` |
| `nginx`        | Local Dockerfile | Reverse proxy/static files         | `81`   |
| `redis`        | Redis 6 Alpine   | Cache / asynchronous communication | `6379` |

### Frontend Compose

| Service    | Build            | Purpose                           | Port |
| ---------- | ---------------- | --------------------------------- | ---- |
| `frontend` | Local Dockerfile | React application served by Nginx | `81` |

> **Port note:** The supplied Compose files map both the backend Nginx service and frontend service to host port `81`. Running both Compose stacks simultaneously on the same Docker host will cause a port conflict. In a deployment where frontend and backend are separate services, assign distinct host ports or place them behind a single reverse proxy.

## Authentication

The API uses **JWT (JSON Web Tokens)** for authentication through Django REST Framework Simple JWT.

The typical authentication flow is:

```text
User
  │
  ├── Register
  │
  └── Login
        │
        ▼
   Access Token
        │
        ▼
 Authorization: Bearer <token>
        │
        ▼
    Protected API
```

Clients should send the access token with protected API requests using the standard authorization header:

```http
Authorization: Bearer <access-token>
```

JWT configuration should be reviewed before production deployment, particularly token lifetime, refresh-token behavior, signing configuration, and secure transport.

## Role-Based Permissions

The backend supports role-based authorization to control access to protected resources.

Permissions should be enforced at the API level rather than relying solely on frontend visibility. This ensures that users cannot bypass authorization simply by sending requests directly to the API.

Typical protected operations may include:

* User-specific resources
* Prediction functionality
* File management
* Administrative operations
* Management of application data

## File Uploads

The backend supports file uploads.

Uploaded files should be validated on the server before being persisted or processed. Recommended production controls include:

* Validate file type and extension.
* Validate file size.
* Generate safe filenames.
* Do not trust user-provided filenames.
* Restrict upload locations.
* Validate uploaded data before passing it to ML components.
* Configure appropriate media storage for production.

## Nginx

Nginx is used as part of the deployment architecture.

The backend configuration mounts the shared static volume:

```text

```

This allows Nginx to serve Django static files independently from the application process.

* TLS/HTTPS termination

* Static files

* Security headers
